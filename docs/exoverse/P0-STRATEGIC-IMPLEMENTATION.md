# Public launch priorities

1. Land the source qualification stack in dependency order. Require current
   Linux and macOS receipts for CLI and MCP, including wrong-fingerprint and
   edited-paper rejection. Owner lane: release engineering. Verifier: hosted
   CI and independent review. No model budget.
2. Make projects, frozen specs and Harbor studies discoverable from the plugin
   skill. Test that fresh hosts can select the correct path and independently
   verify a Harbor receipt. Owner lane: onboarding. Dependency: study stack.
   No model budget for deterministic studies.
3. Qualify the release ZIP and manifest at a version-aligned revision. Run
   fresh Codex and Claude Code installation and minimum-Python tests, then
   measure unaided time to the first verified study. Owner lane: release
   engineering. Verifier: independent trial. Publishing requires owner
   authorization for the exact artifact.
