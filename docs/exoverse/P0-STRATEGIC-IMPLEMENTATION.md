# Public launch priorities

1. Land the source qualification stack in dependency order. Require current
   Linux and macOS receipts for CLI and MCP, including wrong-fingerprint and
   edited-paper rejection. Owner lane: release engineering. Verifier: hosted
   CI and independent review. No model budget.
2. Make projects, frozen specs and Harbor studies discoverable from the plugin
   skill. Test that fresh hosts can select the correct path and independently
   verify a Harbor receipt. Owner lane: onboarding. Dependency: study stack.
   No model budget for deterministic studies.
3. Qualify the release ZIP and manifest at a version-aligned revision. Run
   fresh Codex and Claude Code installation and minimum-Python tests, then
   measure unaided time to the first verified study. Owner lane: release
   engineering. Verifier: independent trial. Publishing requires owner
   authorization for the exact artifact.

## Browser and workflow wave follow-up

- Native agent adapters must scope each child's provider environment and
  exclude provider credentials from version probes. The agent runtime lane
  owns synthetic marker tests and independent exact-head review.
- The release lane must build and qualify a ZIP from an exact source revision
  with fresh Claude Code and Codex profiles. Record the archive checksum,
  minimum Python version and offline checks. Treat each archive revision as a
  distinct qualification.
- The research lane must verify a bounded route for both live arms and a
  researcher-authored rubric before the paid comparison. Keep the offline
  source flow as the zero-budget control.

## Research evidence wave follow-up

- Release lane: build twice from the same exact version and source revision,
  compare archive bytes, then exercise both agent hosts, the offline browser
  example and Harbor from the extracted package. Record each coverage lane.
- Onboarding lane: route researchers to project, spec and Harbor commands in
  the installed research skill. An unaided researcher should be able to run
  a study and hand off evidence a second person can verify without a key.
- Runtime lane: keep live comparisons gated on a verified provider route,
  shared durable reservation, gateway-only network access and approved
  scoring rubric. Confirm a request can never bypass its reservation.
